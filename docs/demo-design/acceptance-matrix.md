# Plinth acceptance and verification matrix

Status: design specification, acceptance and verification. Design only: nothing here is built or run. Owned by the Plinth specification set in `docs/demo-design/`, under the precedence of `spec/README.md`, then the amendments in `selection-rationale.md`, then the spec documents, then `revised/04-emergent-composition.md`. Where this matrix disagrees with a source, the disagreement is listed in section 4. Where the README's resolved decisions (consistency pass) settle a disagreement, section 4 records the ruling and this matrix follows it.

## 1. How to read this matrix

- **Scope.** Every acceptance criterion (AC) defined in `spec/01` to `spec/09`, `implementation-plan.md` and `presentation-script.md` appears once in section 2. That is 639 rows, counted by a parser over the source files. Rows are extracted, not retyped, so the criterion text is abridged from the source and never reworded.
- **Qualified ids.** An AC id is written as `<id> [<doc>]`, where `<doc>` is the number of the document that defines it (`19` is `implementation-plan.md`, `20` is `presentation-script.md`). The same id is defined in more than one document for 83 ids, with different meanings (gap G2). The `‡` mark on a row flags such an id.
- **Labels.** `Guarantee` means enforced by code and covered by a named test. `Target` means a design goal, measured before it is claimed. `Budget` is a configured ceiling that is measured. A `†` means the source gives no label on that line and this matrix took the document's default (`Guarantee`). Those rows are listed as a gap (G26).
- **Verification.** `named test` gives the test name the source states. `measurement` is for a Target, reported by the rehearsal report. `rehearsal assertion` is a Playwright or script beat check. `observable on stage` is a beat check with no test name. `no test named in source (gap)` marks a criterion that has no test name in its source. Such a criterion cannot be counted as a Guarantee until a test with that name exists (gap G25).
- **Beat.** The beat of the five-minute script in which the criterion is shown, taken from the source text or from the beat tables in `spec/08` §15.5 and `presentation-script.md`. `all` means the criterion covers the whole run. `—` means the source ties it to no beat.
- **Layer.** The layer of `implementation-plan.md` §19 that delivers the criterion (`L0` foundations to `L11` rehearsal, `CP-GATE` for the agent gate, `Spike` for SP-AWS and SP-MCP). The layer is assigned by the criterion's area, with per-criterion overrides where the source names one. Overrides are a judgement of this matrix and are open to review.
- **Feature.** The feature group the criterion belongs to, from the section of the source that defines it.

## 4. Gaps and conflicts found while building the matrix

Each gap is a fact found in the sources. A gap marked Resolved is settled by the README's resolved decisions (consistency pass), and this matrix follows the ruling. The other gaps remain open for the orchestrator or the README owner to decide, and the owning document then changes.

**G1. Commit-rule identifiers differ across documents.** `spec/03` §6, `spec/04` §0.2, `spec/05` §8.4, `spec/06` §6 and `spec/08` §15.4 each define a different rule table. Examples: the ops-channel rule is `R-RULE-CREATE` in 03, 04, 05, 06 and the script, but `R-RULE-NOTIFY` in 08 (AC-CRT-6, AC-REH-4). Undo is `R-UNDO` (04, 06), `R-UNDO-OWN` (03, 08) or `R-UNDO-HUMAN` (script); grant undo is `R-UNDO-GRANT` (03, 04, 06). Layout and title edits are `R-LAYOUT` and `R-TITLE` (04) or `R-HUMAN-DIRECT` (05). The fallback is `R-NO-MATCH` (03) or `R-UNMATCHED` (06). Affects AC-AUTH-10 and -11, AC-RUL-6, AC-MCP-13, AC-PRV-6, AC-CRT-1 to -19, AC-REH-4. One closed table is needed, and every row needs one test under one id. **Resolved (ruling 5):** 03 §6 is the single closed table, and the other documents cite its ids without keeping their own tables. The renames are R-RULE-NOTIFY to R-RULE-CREATE, R-UNMATCHED and R-NO-MATCH to one fallback id, R-UNDO to R-UNDO-OWN, R-UNDO-GRANT to R-GRANT-UNDO and R-IDENTITY to R-PRINCIPAL.

**G2. Acceptance-criterion ids are not unique.** 83 ids are defined in two or more documents with different meanings. AC-KER-1 is `uri_stable_replay` in 01 but `commit_equivalence` in 08 and 19. AC-DRV-1 to AC-DRV-13 name different tests in 08, 09 and 19. AC-DATA-1 to -3 mean partition visibility in 05 and history reproduction in 09. AC-AUT (08) and AC-AUTH (03) cover the same topic under two prefixes, and 07 uses AC-DEP-01 where 08 uses AC-DEP-1. The matrix qualifies each id with its document. The owning documents need one namespace per document. **Resolved (ruling 20):** this matrix qualifies each id with its owner document, and the owning documents rename the colliding ids.

**G3. Who may undo an approved grant, and whether it needs approval.** `spec/03` §7.4 and its table classify the undo as `R-GRANT-UNDO`, auto after preview for `grant:admin` holders. `spec/04` §5.6 and decision 7 require approval by a `grant:admin` holder. `spec/06` §4.3 refuses the undo on MCP. The script (beat 7, decision 9) commits it as `R-UNDO-HUMAN` with no approval, which the script itself marks as outside the amendments. README beat 7 describes the undo without an approval step. Affects AC-AUTH-18 [03], AC-WF-25 [04], AC-FE-AUD-3 [04], AC-SCRIPT-10 and AC-REH-7 [08]. This needs an owner decision, and the script's beat 7 depends on it. **Resolved (rulings 3 and 4):** R-GRANT-UNDO is automatic after preview for holders of grant:write on the resource, with no second approval, and is audited as grant.widened and notified. R-UNDO-HUMAN is replaced by R-GRANT-UNDO.

**G4. ## 5. Canonical facts the matrix had to decide

These are the points where the sources are silent, conflict, or where this matrix had to choose. Each is a choice for the owner to confirm or override.

- **D1. Identifiers.** Every criterion is listed under its own source id, qualified with its document number, so no criterion was renumbered and no two are merged. Equal ids with different meanings are kept apart (G2).
- **D2. Labels.** Where a source gives no label the matrix uses `Guarantee` and marks the row †. No Target was inferred from a number.
- **D3. Verification method.** A test name is taken only where the source states one, from its test column, a backticked name after "Test", or a backticked name that begins the criterion. Where the source gives none, the row is `no test named in source (gap)`, or `rehearsal assertion` for `AC-REH`, `AC-SCRIPT` and the Playwright rows, or `measurement` for a Target.
- **D4. Beat.** Taken from the beat number in the criterion text or from the beat tables of 08 §15.5 and the script. Only README windows were used as the reference. The script's beat windows agree with the README; 08 and 09 do not (G18).
- **D5. Layer.** Assigned by area from `implementation-plan.md` §19, with per-criterion overrides chosen by this matrix (for example AC-KER-5 to -8 of 01 are L3, the query layer). The overrides are judgements and should be reviewed by the plan's owner.
- **D6. Coverage.** A capability, rule, infrastructure item or amendment is covered when at least one criterion checks its property. Coverage was judged from the criterion's text, not from its label. P20 has no criterion and is reported as a gap (G24).
- **D7. Canonical facts left open.** The virtual demo date and the seed (G16) and the fault onset time (G17) are not fixed by the canonical facts or the rulings, so the matrix records the conflicting values and does not choose one. The clock rate (G13), slack pool (G14), preview token lifetime (G6), approver's permission (G4) and grant-undo rule (G3) are now fixed by the rulings.
- **D8. Test names reused.** Where two documents name a test with the same name but different thresholds (`replay_reproduces`, G28), the matrix keeps both rows and does not decide which is the test.
- **D9. Sankey and geo.** Amendment P1 is binding over 08 AC-UI-2 (G19). The matrix maps AC-UI-2 as a conflict and not as a coverage of P1.
- **D10. Script decisions.** Script decisions that go beyond the README (12x, `R-UNDO-HUMAN`, `ui` and `system` trace tags, the 2 s acknowledge bound) are reported as gaps where they conflict with a spec, and are otherwise taken as written. Rulings 4, 7 and 12 settle three of them (`R-UNDO-HUMAN`, 12x and the trace tags).
